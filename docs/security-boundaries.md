# Security and privacy boundaries

## Authorized boundary

This lab is limited to the user's Windows host, WSL2 Ubuntu, loopback (`127.0.0.1`), synthetic files, and explicitly isolated local services. The lab does not scan public addresses, employer systems, school systems, neighbors' networks, or production services. The baseline scripts keep external checks disabled unless an operator explicitly opts in and confirms the destination is allowed.

## Data handling rules

- Use fictional warehouse, inventory, ERP, and user names only.
- Do not store credentials, private keys, access tokens, cookies, or personal data.
- Keep raw reports and packet captures under ignored generated directories.
- Sanitize IP addresses, MAC addresses, hostnames, usernames, and DNS suffixes before publishing screenshots or documentation.
- Capture only packets generated by the local lab. Delete any capture that contains unrelated traffic.
- Review `git diff --check`, `git status`, and a secret-pattern scan before publishing.

## Change-management controls

- Prefer localhost and WSL over physical adapter, router, DNS, or firewall changes.
- Use a temporary directory and a temporary process for each scenario.
- Record the before-state and the recovery action in the ticket.
- Never use `--force`, administrator privileges, or destructive cleanup unless the phase explains why it is needed.
- Stop and escalate if a failure appears to involve an external or production system.

## Tool boundaries

Wireshark/TShark captures are restricted to the loopback interface and traffic generated by the test harness. `tshark -D` and capture filters are reviewed before capture. The project does not use cloud resources, Docker, Kubernetes, Azure, AWS, or paid services for the minimum lab.

## Privacy review before GitHub publication

1. Search tracked text for private-key headers, tokens, passwords, and real names.
2. Confirm `.gitignore` excludes `.env`, key/certificate formats, tokens, secrets, credentials, private directories, and packet captures.
3. Inspect every screenshot at readable resolution.
4. Confirm reports are generated under ignored paths.
5. Confirm the remote visibility matches the user's decision. A private repository is the safer default until sanitization is complete.
